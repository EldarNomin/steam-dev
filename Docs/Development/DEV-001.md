## Первый запуск на Windows

1. Установить Unity **6000.3.25f1** через Hub, включая **Windows Build Support (Mono)**. Активировать подходящую лицензию обычным способом Unity Hub.
2. Получить ветку `feature/DEV-001-unity-baseline`. В Hub: **Add → Add project from disk**, выбрать корневую папку `steam-dev` с Assets/Packages/ProjectSettings. Не создавать поверх неё второй проект.
3. Открыть проект, дождаться Package Manager и компиляции. При ошибке остановиться: не считать импорт успешным по наличию меню.
4. Выполнить **Cosmic Catch → Setup → Create baseline**. Открыть `Assets/_Game/Scenes/Boot.unity`, нажать Play.
5. Ожидается платформа, условный корабль, грузовой терминал, оранжевая фигура краба и надпись «КОСМОЛОВ». Игрок ещё не ходит. Проверить отсутствие розовых материалов и ошибок Console. Кнопка «Выйти» проверяется в standalone; в Editor она не завершает Play Mode.
6. Выполнить **Cosmic Catch → Build → Windows x64**. Результат: `Builds/Windows/CosmicCatch.exe` и `Reports/windows-build.json`. Запустить exe и проверить картинку, русский текст, кнопку выхода и Player.log.
7. Повторить Setup: сцена и материалы не должны замениться, GUID Boot должен остаться прежним, Boot в списке сборки присутствует один раз.
8. Закоммитить созданные Assets вместе с .meta, packages-lock.json и ProjectSettings. Отчёт проверки приложить к PR; exe, Library, UserSettings и Logs не коммитить.

Setup — явная настройка нового проекта: применяет название, Linear color space, Mono/DX11, оконное разрешение, текстовую сериализацию и один URP для всех уровней Quality. После дальнейших изменений этих параметров не запускать Setup как универсальное средство ремонта. Уже существующие Boot/материалы сохраняются; посторонний активный pipeline и конфликтующие типы файлов вызывают ошибку. Автоматического редактирования сцены при открытии Editor нет.

## Запуск из PowerShell

Закрыть Editor для этой папки. Из корня репозитория:

```powershell
$unityEditor = 'C:\Program Files\Unity\Hub\Editor\6000.3.25f1\Editor\Unity.exe'
.\Tools\Unity.ps1 -Action Setup -EditorPath $unityEditor
.\Tools\Unity.ps1 -Action Build -EditorPath $unityEditor
```

Нужны установленный Editor, модуль сборки, лицензия и доступ к Unity Registry. Скрипт не устанавливает Unity и не подключает MCP. Первая загрузка пакетов может занять время. Логи: `Reports/unity-setup.log`, `Reports/unity-build.log`. Ненулевой exit code — неуспех; скрипт проверяет существование сцены/отчёта/артефакта, удаляет предыдущий build report перед новой попыткой. Успешная сборка не доказывает успешный gameplay.

## Проверка без Editor

Python 3.10+:

```bash
python Tools/validate_project.py
python -m pip install -r Tools/requirements-validation.txt
python Tools/validate_project.py --syntax
```

Проверяются маркеры, JSON, metadata/GUID, разделение Editor/Runtime, локальные ссылки и опционально грамматика C#. Парсер не проверяет наличие Unity API, типы, разрешение пакетов или запуск сцены.
