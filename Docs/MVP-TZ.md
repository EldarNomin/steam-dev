# ТЗ: Космолов, MVP 0.1.0

Дата: 2026-10-07. Владелец решения: Эльдар. Все решения — исходная спецификация для прототипирования; удобство, удержание и коммерческий спрос ещё не проверены.

## 1. Продукт

Жанр: кооперативное приключение с физической охотой, сбором добычи и развитием. Платформа MVP: Windows x64, мышь и клавиатура, русский интерфейс; строки вынесены из кода для дальнейшего перевода. Камера от первого лица. Одиночная игра и онлайн-команда 2–4 человека. Нет PvP. Игроки — работники службы отлова для космического питомника.

Обещание: «Поймай странное существо и довези его до корабля, пока оно не утащило тебя». Источники юмора — взаимодействия понятных правил, реакции существ, борьба с грузом и помощь товарищей. Нарочитые ошибки управления не заменяют удобное движение.

## 2. Игровой цикл

Станция → выбор контракта и снаряжения → высадка → разведка и приманивание → захват → перевозка → выбор вернуться или рискнуть → сдача → развитие / необязательные азартные занятия → новая экспедиция.

Целевой успешный заход: 10–20 минут; в MVP нет обязательного таймера. «Ещё одна добыча» ограничивается четырьмя грузовыми местами и опасностью существ. Корабль на поверхности неподвижен; полёт между точками — переход сцены, не управление космическим кораблём.

## 3. Отличия от референса

Из How to Fish берём цикл добычи, продажи, улучшений, редких вариантов, опасных регионов, задач, трюков и необязательного гэмблинга. Способы захвата, сопротивление при доставке, ограничения груза и правила случайных наград проектируем сами. Чужие код, модели, звуки и интерфейсы не являются частью ТЗ.

Главное собственное отличие: сопротивляющаяся живая добыча становится переносимой задачей. Один и тот же трос удерживает зверя, цепляется за опору и помогает извлечь груз. Кооператив облегчает задачи, но обязательных действий на двух игроков нет.

## 4. Границы MVP

Включено:

- Одна станция: контрактный терминал, магазин, приёмка добычи, азартный терминал, капсульный автомат, каталог.
- Два компактных уровня, собранных вручную: Каменный пояс и Газовый кратер. Обычная вертикальная гравитация, отдельные зоны слабой гравитации.
- Три базовых вида: краб, надувной зверь, электрический слизень. Один элитный краб — босс-контракт, использующий существующую основу с отдельным паттерном.
- Три варианта каждого базового вида: обычный, светящийся, массивный. Девять записей коллекции, элита отдельно.
- Гарпун, приманки, стационарные опоры, контейнеры; улучшения троса, контейнера и сканер. Оглушение встроено в гарпун после покупки модуля.
- Один общий бюджет и личные развлекательные кошельки внутри сохранения мира.
- Шесть одноразовых этапов развития, затем повторяемые контракты.
- Один азартный терминал с тремя размерами ставки; один тип капсулы с девятью косметическими наградами.
- Сохранение прогресса на станции, одиночный режим, онлайн на 2–4 игроков, вход по коду подключения.
- Обучение через первый контракт, настройки чувствительности, громкости и уменьшения тряски камеры.

Позже: пилотирование, открытая галактика, сферическая гравитация, произвольная невесомость, PvP, миграция хоста, подбор незнакомых игроков, голосовой чат, рыночная торговля, автоматическая процедурная генерация уровней, Steam achievements, контроллеры, дополнительные азартные игры. Эти функции не блокируют приёмку MVP.

## 6. Пользовательские потоки

Первый запуск: имя профиля → новый мир → станция → бесплатный комплект и первый контракт → посадка → подсказка по приманке → опора и трос → контейнер → возврат → сдача → первое улучшение.

Кооператив: хозяин загружает мир → открывает лобби → получает код → гости подключаются → хозяин выбирает задание → каждый подтверждает готовность → экспедиция. На станции разрешён вход; в экспедиции новый вход запрещён.

Гэмблинг: игрок подходит к терминалу → видит личный баланс, ставку и все выплаты → выбирает ставку → подтверждает → система фиксирует результат → играет короткую анимацию → показывает выплату и новый баланс.

Капсула: игрок видит цену, вероятности, гарантии и собственную коллекцию → подтверждает → результат фиксируется → награда раскрывается → игрок может её экипировать. Экипировка меняет только визуал, не характеристики.

## 7. Риски и критерии решения

Главный технический риск — трос и переносимый груз в сети. Его проверяем до второго региона и косметики. Визуальная леска не требует физической цепи из десятков тел. Главный продуктовый риск — однообразная доставка: каждый вид должен менять действия игрока, а не только число HP.

Проверка удовольствия: минимум пять внешних участников, не авторы игры; минимум три без подсказок проходят первый цикл и хотят повторить охоту. Это внутренний критерий следующей итерации, не прогноз продаж. Если ядро не нравится, меняем взаимодействия, а не добавляем капсулы.

## 8. Готовность MVP

Все MVP-001…MVP-020 проверены по ACCEPTANCE.md; собрана Windows-версия; пройден маршрут от пустого мира до элитного контракта с выключенным гэмблингом; проведена сессия на четырёх клиентах; проверены сохранения и восстановление; хотя бы одна локация имеет законченный свет, звук и единый художественный стиль. Нельзя считать MVP готовым по наличию документов, кода или макетов.
