# DEV-002: первый игрок и взаимодействие

Исполнитель: локальный GLM / z.code. Codex: ревью через GitHub. Статус: **READY AFTER DEV-001 VALIDATION**, реализация NOT STARTED на момент передачи. Ссылки: [backlog](../BACKLOG.md), [HUNT](../Specifications/HUNT.md), [баланс](../Data/balance.v0.1.json), [приёмка](../ACCEPTANCE.md), [передача](../AI/LOCAL-AGENT-HANDOFF.md).

## Условие начала и результат

Нужны подтверждённые import/compile, сохранённая Boot.unity, отсутствие блокирующих ошибок Play Mode из DEV-001. Если baseline не запускается, сначала закончить его проверку. Ветка `feature/DEV-002-player` создаётся от проверенного commit с настоящей сценой и настройками, а не от старого docs-only main.

После задачи игрок от первого лица ходит по станции, смотрит мышью, прыгает, взаимодействует с тестовым терминалом и открывает настройки. Низкая гравитация проверяется в обозначенной тестовой зоне. Добычи, оружия и наград ещё нет.

## Поведение

| Действие | Требование |
|---|---|
| WASD | Скорость 5 м/с; диагональ не быстрее прямого движения |
| Мышь | Поворот тела и камеры; вертикальный угол ограничен; камера не переворачивается |
| Space | Высота прыжка 1,2 м при обычной гравитации; прыжок только с земли, без повторных прыжков в воздухе |
| Гравитация | 9,81 м/с² обычно; 3,0 в тестовой зоне; при выходе ускорение переходит к обычному за 0,3 с |
| E | Одно взаимодействие на нажатие; только доступная цель перед камерой в пределах 2 м, препятствие перекрывает цель |
| Прицел | Читаемая подсказка `E — Проверить терминал`; при уходе взгляда/за пределы дальности подсказка исчезает |
| Тестовый терминал | Показывает короткий ответ `Терминал готов`; не выдаёт деньги и не запускает экспедицию |
| Esc | Открывает/закрывает простое меню; в меню курсор свободен, движение/обзор/взаимодействие блокируются |
| Настройки | Чувствительность мыши, инверсия Y, общая громкость; значения сохраняются локально и применяются после перезапуска |
| Потеря фокуса | Управление не застревает после возврата; курсор захватывается только при возвращении в gameplay |
| Ошибка позиции | Края тестовой площадки ограничены; падение ниже безопасной границы возвращает к точке старта до внедрения HP/смерти DEV-005 |

Настройки доступности тряски понадобятся при её появлении; в этой задаче тряску/качание камеры не добавлять. Скорость с грузом 3,5 м/с реализуется вместе с переносом DEV-005; текущие значения не считать полным выполнением TC-004.

## Реализация и границы

- Использовать существующий Input System; не переходить на legacy Input. Проверить фактический input backend в Editor, сохранить необходимые настройки в Git. Input actions/ссылки, если используются, создать и связать через Editor с сохранением .meta.
- Для первого solo-контроллера допустим CharacterController. Не соединять на одном игроке одновременно несколько конкурирующих способов управления физикой. Отделить чтение ввода от движения так, чтобы DEV-006 могла подключить авторитетную сетевую модель без переписывания UI/настроек.
- Один активный игрок, одна gameplay-камера и один AudioListener. Перенести существующий экран станции так, чтобы он не закрывал прицел и подсказки. Не потерять существующие ссылки/материалы Boot.
- Простая точка расширения взаимодействия для терминала и будущих контейнеров. Проверять ближайшую цель лучом, исключать самого игрока и учитывать препятствия. Не строить универсальный framework.
- При отключении игрока освобождать принадлежащие ему input actions/подписки; не Dispose общие actions другого компонента. Восстанавливать курсор/состояние меню при завершении Play Mode и повторном запуске.
- Допустимая область: Runtime/Player, Runtime/Interaction, Runtime/Presentation, нужные input assets/prefabs, Boot/тестовая зона, узкое расширение Editor setup и тесты. Все новые Assets с .meta; переносы через Editor.
- Параметры движения брать из утверждённого [баланса](../Data/balance.v0.1.json). Не менять числа отдельно от spec. Баланс-файл пока расположен в Docs: не читать этот путь напрямую из standalone. Если вводятся runtime definitions, явно документировать перенос значений и единственный способ их обновления.
- Не реализовывать NGO/Relay, трос, AI существ, азартные операции или экономику. Не ставить дополнительные ассет-паки и не обновлять Editor/URP для этой задачи. Платные ассеты в публичный Git не добавлять.

## Проверка и сдача

1. Console: успешная компиляция после изменений; отсутствие новых ошибок при входе/выходе из Play Mode.
2. Движение: сравнить прямой и диагональный путь за одинаковое время; проверить землю/прыжок/столкновения и отсутствие двойного прыжка. Измерить исходные скорость/высоту, а не только субъективно оценить.
3. Низкая гравитация: вход, выход и повторный вход; численно проверить заданные ускорения/переход; убедиться, что после выхода не остаётся режим вечного полёта. Нужен визуальный маркер зоны без служебных подробностей на игровом экране.
4. Терминал: близко, дальше 2 м, за стеной, взгляд в сторону, удержание E. Только одно событие на нажатие и только при допустимых условиях.
5. Меню/настройки: в меню не двигаться и не взаимодействовать; изменить значения, перезапустить и проверить сохранение; проверить alt-tab и повторное открытие меню.
6. Повторно войти/выйти из Play Mode несколько раз; проверить отсутствие дублирующихся actions/подписок/AudioListener и зависшего курсора.
7. Собрать Windows exe и повторить основной сценарий в standalone. Настройки не должны зависеть от AssetDatabase/UnityEditor или файла в Docs.
8. Добавить автоматические проверки только для значимых рисков, например нормализации движения или блокировки взаимодействия препятствием. Не заменять Editor/standalone проверки тестами, которые просто повторяют значения полей.

Сдать изменённые исходники, настоящие prefab/scene/input/settings и .meta, краткий `Docs/Development/DEV-002-RESULT.md` с commit, окружением, expected/actual, статусом каждой проверки, проблемами и evidence. Приложить короткое видео или скриншоты движения/меню/подсказки к PR. Логи и exe не коммитить. Не объявлять TC-004/TC-028 целиком пройденными: дальнейшие механики и полный MVP ещё отсутствуют.

Критерий готовности DEV-002: указанные сценарии работают в Editor и Windows standalone; чужие изменения сохранены; локальные результаты опубликованы в GitHub и доступны для ревью. Дальше — DEV-003, один живой краб с приманкой и читаемыми фазами.
