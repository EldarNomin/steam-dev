## Замечания

### F1 — P1: повторная сборка с восстановленным кешем не устанавливает шаблоны

Место: `.github/workflows/cosmic-magnet.yml:198–227`, особенно условие на строке 213.

Кешируется только `~/godot-cache`, а шаблоны перемещаются в `%APPDATA%/Godot/export_templates/4.5.1.stable`. На новом раннере с cache hit восстановленный Godot уже существует, поэтому весь блок установки шаблонов пропускается. В целевом каталоге шаблонов нет, release export не сможет их найти. Текущий зелёный run не опровергает дефект: в Windows-логе явно `Cache not found`.

Минимальный ремонт: отделить получение Godot от установки шаблонов; при отсутствии целевого каталога распаковать проверенный кешированный TPZ и установить шаблоны независимо от наличия exe. Альтернатива — кешировать конечный каталог с корректным восстановлением. Проверка закрытия: два успешных Windows-run, второй с подтверждённым cache hit и успешным export/smoke.

### F2 — P2: обещанная консольная диагностика отсутствует в выдаваемом билде

Место: `export_presets.cfg:25`, `.github/workflows/cosmic-magnet.yml:260`, `docs/reports/CM-004-implementation.md` (утверждения о console wrapper).

`debug/export_console_wrapper=1` означает Debug Only, а CI вызывает `--export-release`. Дополнительно upload разрешает только основной exe. Самостоятельно скачанный ZIP действительно содержит ровно один CosmicMagnet.exe; тестер не может запустить обещанный `.console.exe` для диагностики.

Семантика проверена по исходнику Godot 4.5.1: https://github.com/godotengine/godot/blob/4.5.1-stable/editor/export/editor_export_platform_pc.cpp — строки 58 и 180–181 (`copy_wrapper = (mode == 1 && p_debug) || mode == 2`).

Минимальный ремонт: установить режим 2, включить основной exe и console wrapper в artifact, согласовать инструкцию раздачи и проверить их наличие в новом ZIP. Основной exe по-прежнему может содержать встроенный PCK.

### F3 — P2: пакет сдачи не фиксирует актуальную проверенную ревизию

Место: `docs/reports/CM-004-implementation.md:5–7` и таблица проверок; описание PR.

В отчёте нет обязательного поля «Код проверен на SHA», точных команд запуска тестов и неизменяемых ссылок на проверенный run/artifact. PR ссылается на run `38070720890` / artifact `11677200852`, относящиеся к прежнему SHA `d7e9e5c783c1d8b056d3f2d8e6d0739acaba2a1c`, а текущий head — `2a4e5c2`. Утверждение о локальном запуске Windows нельзя однозначно связать с текущим пакетом.

Минимальный ремонт: при повторной сдаче записать SHA кода до документационного коммита, фактические команды, run ID и artifact ID именно этой ревизии. Для локального Windows-запуска указать проверенный artifact/SHA и что реально проверялось. Старые результаты сохранить как историю, не выдавать за запуск нового билда.

F1–F3 также присутствуют в автоматическом ревью PR; здесь они независимо сверены с текущим head. F3 классифицирован как P2: CI текущего head удалось найти и проверить, поэтому это пробел воспроизводимости отчёта, а не доказанное падение игры.
