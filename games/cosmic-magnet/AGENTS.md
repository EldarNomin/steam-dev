# Инструкции для работы над Cosmic Magnet

Эти правила действуют внутри `games/cosmic-magnet/`. Требования пользователя имеют приоритет.

- Перед работой прочитай README, `docs/GAME-SPEC.md`, `docs/DEVELOPMENT-PLAN.md`, `docs/STATUS.md` и `docs/REVIEW.md`.
- Исполнитель GLM начинает только задачу, указанную в STATUS как CURRENT. Текущая задача определяется свежим STATUS; на 2026-10-10 это CM-H01A (docs/CM-H01-GAMEPLAY-HOOK.md). Самооценка не является приёмкой. Прямое поручение Эльдара разрешает этот ограниченный эксперимент до живых проб CM-004; CONTINUE этим не заявляется.
- Один небольшой PR на задачу. Крупный этап можно разделить на несколько связанных PR, согласовав границу с Codex. Не смешивай механику, полный арт и Steam-интеграцию.
- Ветка: `feat/cosmic-magnet/<задача>`. База и target PR указаны в текущем задании: для CM-H01A — `feat/cosmic-magnet/visual-polish`, поскольку принятая цепочка ещё не слита в main. После её слияния обычный target — main. Не пушь реализацию прямо в main, не выполняй force-push, не сливай свой PR без решения проверяющего.
- Стек: Godot 4.5.1 Standard + typed GDScript, 2D, Compatibility. Не меняй движок/версию, не подключай плагины и внешние библиотеки без конкретной необходимости и согласования.
- Не изменяй другие игры. Корневые настройки меняй только при необходимости, описав влияние. CI этой игры отдельный и фильтруется по её путям.
- Простая реализация предпочтительна: обычные сцены, сигналы, небольшие скрипты. Не вводи ECS, DI-контейнер, сетевую архитектуру, генератор контента или универсальный движок.
- Экономика и численные настройки должны храниться в одном машиночитаемом конфиге начиная с CM-002. Правила расчёта не дублируются между HUD и игровой логикой.
- Не коммить `.godot`, движок, временные логи, секреты, личные сохранения или большие сборки. Собственные `.gd.uid`, сцены и исходные ассеты коммить.
- Укажи происхождение и лицензию сторонних ассетов. Бесплатность скачивания не означает разрешение перепубликовать исходники в публичном репозитории.
- Не имитируй игровой экран статичной картинкой. Каждый собираемый предмет должен быть реальным объектом; HUD отображает реальное состояние.
- Для сдачи обнови STATUS, приложи отчёт из REVIEW с SHA, командами и фактическими результатами. Статус реализации — READY_FOR_REVIEW; ACCEPTED выставляет Codex.
- Если движок, Windows, CI или запись видео недоступны, прямо укажи NOT_RUN и причину. Не подменяй запуск чтением кода и не выдумывай успешные проверки.
- При блокере опиши проблему и минимальный следующий шаг. Не расширяй задачу, чтобы обойти отсутствующую проверку.
